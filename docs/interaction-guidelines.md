# WebBridgeKit 交互规范（Interaction Guidelines）

> Status: **Mandatory** — 新增或修改任何用户交互前必读；新交互必须按 §10 checklist 登记。
> 范围：**行为与手势**（怎么操作、操作后发生什么、如何可逆、如何反馈）。
> 视觉 tokens / 组件样式另见 `docs/ui-design-guidelines.md`，两者互补不重复。
> 维护方式：随代码进库；每次交互变更在 §11 变更记录追加一行。

---

## 1. 总则（设计原则）

1. **可逆优先**：任何改变用户数据的操作必须有对称的逆操作，且入口同处
   （在哪里加的就在哪里取消）。右滑能置顶，再右滑就能取消置顶；能收藏就能取消收藏。
2. **手势同义**：同一手势在全 App 只有一种含义。列表手势以 §2 词汇表为准，
   新列表不得发明第二套（历史教训：收件箱与收藏夹曾各一套，2026-09 统一）。
3. **反馈必达**：每个生效的操作必须有可见反馈（HUD / 按压态 / 视觉标记 / 位置变化），
   不允许「点了没反应」（v74 胶囊收藏曾因此被用户报障）。
4. **破坏性操作要么确认、要么可撤销**（§4）。
5. **Fail-closed**：不可信入口（未注册应用、验签不过）拒绝并说明，不静默降级。

## 2. 手势词汇表（全 App 统一）

| 手势 | 语义 | 现状覆盖 | 备注 |
|---|---|---|---|
| 行右滑（leading） | 置顶 / 取消置顶（开关） | 收件箱、收藏夹 | **整滑直触发**（`performsFirstActionWithFullSwipe = true`），半滑出按钮可点 |
| 行左滑（trailing） | 删除 | 收件箱、收藏夹 | destructive；收藏夹删除有确认弹窗；收件箱直删（撤销方案待拍板，§4） |
| 点按行 | 打开 / 进入 | 所有列表 | |
| 长按 | 编辑 / 操作表 | 收藏夹 | |
| 下拉 | 刷新 | 收藏夹等 | |

新列表交互强制沿用本表；确需新手势时先在本表登记再实现。

## 3. 成对操作登记表（有「设置/添加」必须有「取消/移除」）

| 操作 | 逆操作 | 入口 | 反馈 |
|---|---|---|---|
| 收藏页面 | 取消收藏 | ⋯ 菜单（普通壳/沉浸式）、星标按钮 | HUD「已收藏/已取消收藏」+ 菜单标签随态切换（开关语义） |
| 置顶 | 取消置顶 | 列表行右滑；置顶管理页 | 行浮顶 + Lucide pin 图标 |
| 缓存模式开 | 缓存模式关 | （数据层通道在：`cacheModeToggle`/`updateCacheModeAsync`；当前无独立 UI 入口——S4 已移除 cell 开关，WebAccessViewController 是死代码。补 UI 时必须同时给出开与关） |
| 主题深 | 主题浅 | 设置 | 全部 CGColor 随切重解析（§8） |
| 自托管推送配对 | 重置推送地址 | 设置 → 自托管推送 | 重置销毁本地身份再重新配对 |
| 网页授权授予 | 授权撤销 | 权限与原生能力页 | 授权可列表管理、逐条撤销 |

规则：新增任何 toggle/添加类交互，必须同时设计逆操作并登记到本表；
只有单向操作的交互（如「分享」「复制」这类无状态动作）需在 PR 说明为何豁免。

## 4. 破坏性操作规范

- **确认型**（现状）：删除收藏 → 弹窗确认。
- **可撤销型**（目标形态，待拍板后落地）：删除即时生效 + 撤销 toast。
- **禁止单向直删**：同一对象的多条删除路径必须同级处理
  （收件箱现状即违规实例：卡片左滑直删无确认，而详情删除/分组删除/清空全部都有确认）。
- 收件箱整滑直删目前无确认无撤销，属已知欠账；三个待拍板事项
  （预览行数/删除撤销形态/上一下一条方向）见 AGENTS.md「收件箱 × Bark 对标
  多智能体 UX 评审」节（原 /tmp/drel-ux-review/ 产物已被清理，该节为唯一存档）。

## 5. 反馈规范

- **HUD**：收藏/取消收藏等轻量结果用 HUD；HUD 存续期会吞掉后续 tap
  （UI 测试已知坑，见 §9）。
- **按压态**：卡片按压高亮必须限制在圆角内（`selectionStyle = .none` +
  `setHighlighted` 换背景色）；零延迟按压用 `TouchFeedbackView`，
  禁止 `require(toFail: pan)`（按压会在抬手才出现）。
- **置顶视觉**：行首 Lucide pin 图标（`xs` 尺寸、主题色）+ 浮顶位置，
  不得只用 emoji 或仅靠位置表达。
- **空态**：搜索无结果与零数据必须可区分（UX 评审 P0，待落地）。

## 6. 列表排序与分区规范

- 列表默认序：**置顶浮顶 + 组内创建时间倒序**（最新在前）。
  已落地：收藏夹（FavoriteViewModel）、首页收藏格子（MainViewModel）；
  收件箱按消息时间倒序 + 置顶浮顶。
- 禁止手动拖拽排序与时间排序混用（时间序下拖拽是假功能，收藏夹已移除）。
- 置顶行的可辨识性：pin 图标 + （分组时）独立分区头。
- 分区头语义要自解释（「置顶收藏」「收藏」）；徽标/计数语义不明会进 UX 评审。

## 7. 边界与安全交互

- 外部/推送/消息内链接统一经 `DrelExternalAppLinkOpener` / `DrelMessageOpenPolicy`
  路由：受信注册应用→沉浸式；未注册→fail-closed 弹「应用未注册」，绝不静默降级开浏览器。
- 沉浸式页面退出：胶囊控件（收起/展开→退出格）；沉浸式断言用
  `navigationBars.firstMatch.exists == false`。
- 打开网页必藏底部 tab，返回后回显（tab 显隐是「进入/退出网页壳」的配套反馈）。

## 8. 主题与视觉行为规则（交互相关的硬性约束）

- **CGColor 不许只解析一次**：所有 `layer.borderColor`/`backgroundColor`(CGColor)
  必须随 `traitCollectionDidChange` 重解析；复用池 cell 在 `configure` 里再解析一次
  （2026-09-18 黑边框事故整案）。
- 图标语言：功能图标用 Lucide（`LucideIcon.pin` 等），与收件箱/收藏夹一致；
  禁止 emoji 当功能图标。

## 9. 可测试性约定（交互落地的一部分）

- 每个 `UITableViewCell` 必须设运行时稳定 a11y 标识（如 `favorite.card.<id>`、
  `notification.card.<id>`）；列表断言一律运行时按标识取行，禁止硬编码位置
  （线上推送会让顺序漂移）。
- UI 测试手势配方：整滑触发用
  `coordinate(dx:0.1).press(forDuration:0.05, thenDragTo: dx:3.0)`；
  小距离 `swipeRight()` 触发不了 action。
- 开关语义的测试必须先归一到未生效态再操作（「取消收藏」重跑陷阱）；
  HUD 后的操作要用**条件重试**（tap→等→没有再 tap），不能盲目双击
  （面板开着时第二次 ⋯ 是收起）。
- 「同步写 + 立刻重读」必踩写后读竞态：写走 async 等提交完成后再刷列表
  （收藏夹删除要点两次的事故）。

## 10. 新增/修改交互 checklist（PR 自查）

1. 有逆操作吗？→ 没有：PR 说明豁免理由；有：登记进 §3 成对表。
2. 手势/位置符合 §2 词汇表吗？新列表沿用右滑置顶/左滑删除。
3. 反馈是什么（HUD/按压态/视觉标记/位置变化）？禁止无反馈。
4. 破坏性操作走 §4 哪条路（确认/撤销）？
5. 深浅主题都验过吗？CGColor 重解析了吗（§8）？
6. 文案 zh/en 双语齐了吗？键名语义化（缺键会直接显示 key）。
7. a11y 标识 + UI 测试（含开关归一、整滑配方）加了吗？
8. 本文档 §2/§3/§11 更新了吗？
