# WebBridgeKit 首页重设计（选定方案 3）

## 目标

首页首先让普通用户完成一次真实消息推送，同时保留已缓存 PWA 的管理入口。页面要像原生消费级 iOS 产品，不呈现为开发工具仪表盘。

选定视觉基准：`.design_library/WebBridgeKit/home-redesign/home-v3-selected.png`。

## 信息层级

1. 顶部显示 `WebBridgeKit` 与简短服务状态 `可以接收通知`。
2. 主区域为 `发送第一条通知`：包含标题、内容以及 `用 Safari 发送测试` 主按钮。
3. Safari 在应用外发起真实 HTTP 请求；返回 App 后验证通知接收链路。
4. `我的推送地址` 固定显示在主区域底部，始终提供复制操作。
5. `我的应用` 展示常用或已缓存 PWA 图标。点击应用先进入详情与配置，不直接启动；详情页提供明确的 `打开应用` 操作。
6. `全部 API 示例` 覆盖普通、Markdown、验证码、二维码、图片、聊天和审批。
7. `手册与调试` 作为低层级入口，承载接入文档、日志、网络和缓存工具。
8. 主导航保留 `首页 / 通知 / 设置`。

## 页面状态

### 已有 PWA

显示最多四个常用应用；更多内容进入 `管理`。每个应用的缓存和权限状态只在详情页展开，首页不堆叠技术标签。

### 没有 PWA

保留完整推送测试区；`我的应用` 替换为单行空状态：`还没有添加应用` 与 `连接应用服务`。空状态不能抢占推送主任务。

### 服务异常

推送地址仍可复制；状态文案变为可理解的错误说明，并提供 `重试`。调试详情只在 `手册与调试` 中出现。

## 视觉规则

- 画板：iPhone 内容宽度 390pt；首屏高度 844pt，允许内容区滚动，Tab Bar 固定。
- 背景 `#F8F9FC`，Surface `#FFFFFF`，主色 `#4F6AF6`。
- 主文本 `#1A1D2E`，次文本 `#6B7394`，分隔线 `#E6EAF0`。
- 卡片圆角 16pt，行圆角 12pt；主要按钮高度不低于 48pt。
- 通过间距、字号和分组建立层级；避免嵌套卡片、渐变、大面积阴影和无意义指标。
- 图标使用 Lucide；PWA 使用清单提供的真实应用图标。

## 验收标准

- 新用户无需阅读手册即可识别推送标题、内容和发送按钮。
- 推送地址在首页一步可复制。
- 测试请求明确通过外部 Safari 执行。
- 首页中的 PWA 点击后先进入详情配置，不直接打开网页。
- 所有规范消息类型均能从 API 示例进入可测试示例。
- 调试工具可到达，但视觉权重低于推送和 PWA。
- 无 PWA、服务异常和已有应用三种状态都有明确设计。
