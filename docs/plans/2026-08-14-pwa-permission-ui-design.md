# PWA 原生能力授权 UI 设计

日期：2026-08-14

状态：设计已确认，等待实现

## 目标

为 WebBridgeKit 托管的 PWA 提供两层清晰、可撤销的权限体验：

1. WebBridgeKit 使用品牌化自有 UI，解释 PWA 为什么需要某项原生能力并记录授权范围。
2. iOS 继续负责蓝牙、相机、位置等系统隐私授权，WebBridgeKit 不伪造或替代系统弹窗。

普通标准 PWA 在非 WebBridgeKit 容器中调用 Bridge 时，继续获得结构化的
`NATIVE_MODULE_UNAVAILABLE` 结果，不产生 JavaScript undefined 异常。

## 交付边界

- `Sources/` 提供可复用的权限策略、授权记录、系统状态适配和品牌化授权面板。
- `SuperApp/` 提供 PWA 应用设置、权限列表、产品文案与导航入口。
- `AppTemplate/` 暂不复制完整权限管理页面；公共 SDK API 稳定后只提供最小接入示例。
- PWA HTML 只提供申请理由并触发标准 Bridge 调用，不能自行伪造宿主授权结果。

## 用户入口

采用双入口，并进入同一个权限管理页面：

1. PWA 容器右上角“…” → 应用设置 → 权限与原生能力。
2. 应用中心 → 应用详情 → 权限与原生能力。

权限管理页顶部展示 PWA 图标、名称、来源和安全说明。未使用的能力只能显示为
“尚未请求”，不能在设置页直接预授权。

## 首次申请面板

首次调用受保护能力时展示 WebBridgeKit 自定义底部面板：

- 背景使用 token 化遮罩，底部卡片支持亮色、深色、动态字体和 VoiceOver。
- 顶部展示 PWA 图标、名称、能力图标和“原生能力申请”标识。
- 主标题为“允许「应用名称」使用蓝牙？”等能力相关文案。
- 用途说明独立成区，来源域名始终可见。
- 明确提示允许后仍可能出现 iOS 系统权限确认。
- 点击遮罩、向下关闭或取消均返回取消结果，完成回调只能执行一次。

授权范围：

| 范围 | 行为 |
|------|------|
| 仅这一次 | 只允许当前 Bridge 调用，完成或失败后消耗 |
| 本次使用期间 | 当前 PWA 容器存活期间有效，作为推荐选项 |
| 始终允许 | 持久有效，直到用户撤销或应用身份发生变化 |

“始终允许”不得使用更强的视觉强调，避免诱导长期授权。

## 权限管理页

能力按“需要处理、已允许、尚未使用”组织。每一行同时显示：

- 能力名称与图标；
- WebBridgeKit 授权状态或授权范围；
- iOS 系统状态；
- 当前可执行操作。

示例：

```text
蓝牙 · 本次使用期间
iOS 系统：已允许
```

支持：

- 单项撤销 WebBridgeKit 授权；
- 撤销全部当前 PWA 的 WebBridgeKit 授权；
- 系统拒绝时跳转 iOS 设置；
- 自有撤销确认面板，不混用普通系统 Alert。

撤销不会伪装成修改了 iOS 系统权限。对于蓝牙扫描等持续能力，撤销后必须停止
活动会话和事件订阅。

## 授权身份与生命周期

授权主体由以下信息共同确定：

```text
gatewayIdentity + appID + origin + capability
```

下列情况不得沿用旧授权：

- 切换或移除网关；
- PWA 来源域名变化；
- 卸载 PWA；
- manifest 删除对应能力；
- 签名应用身份发生变化。

页面切到后台不会立即清除“本次使用期间”，但关闭 PWA 容器必须清除。始终允许的
授权需要安全持久化。

## 请求与错误处理

- 同一时间只显示一个授权面板，其余请求排队。
- 同一 PWA 对相同能力的重复请求合并。
- PWA 跳转到其他来源、容器销毁或面板关闭时，请求安全取消。
- WebBridgeKit 已授权但 iOS 拒绝时，不重复展示第一层面板。
- Bridge 返回稳定的系统拒绝、需要设置、用户取消、能力未声明、来源不匹配等错误。
- 通知或深链接只能定位到目标页面，不能直接授予权限或执行敏感操作。

## 验收标准

1. 蓝牙首次调用先出现 WebBridgeKit 自有面板，同意后才可能出现 iOS 系统弹窗。
2. 面板显示真实 PWA 名称、来源、能力和开发者用途说明。
3. 三种授权范围的有效期符合定义，重启后只有“始终允许”保留。
4. 两个入口进入同一个权限管理页，显示一致状态。
5. 单项撤销和全部撤销立即生效；撤销蓝牙时停止活动扫描和订阅。
6. iOS 已拒绝时显示“前往系统设置”，不错误显示为应用内可重新授权。
7. 切换网关、来源或应用身份后不继承旧授权。
8. 并发申请不会叠加多个面板，取消和销毁回调只完成一次。
9. 普通浏览器 fixture 返回 `NATIVE_MODULE_UNAVAILABLE`，不抛出运行时异常。
10. 亮色、深色、动态字体、VoiceOver、iPhone SE 尺寸和 iPad 展示通过验证。

## 实现顺序

1. 补齐授权身份、生命周期和请求队列的 SDK 测试。
2. 用 token 化自定义底部面板替换默认 `UIAlertController` Presenter。
3. 重构 SuperApp 权限管理页并加入双入口。
4. 补齐蓝牙持续会话撤销和系统设置跳转。
5. 更新 UI 测试、截图、文档与 JSBridge 回归门禁。
