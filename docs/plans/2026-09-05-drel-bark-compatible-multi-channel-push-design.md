# Drel Bark 兼容多通道推送设计

## 决策

Drel 采用 Bark 的多服务器模型，而不是“配置自建服务后覆盖官方地址”。官方
`api.drel.app` 与每一个用户添加的自建服务都是独立、可长期保存的通道；当前通道
只决定首页展示、复制的推送地址、示例与通道相关设置。切换不会删除配置、密钥或消息。

## 客户端模型

`PushChannel` 包含稳定 ID、显示名、服务地址、设备 capability (`deviceKey`)、状态及
类型（`official` 或 `selfHosted`）。官方通道不可删除；自建通道可扫码或填写 HTTPS
地址添加。APNs Token 更新时，客户端分别向每一个启用通道注册，因而官方和自建服务
可以并行投递。

首页右上角提供当前通道菜单。切换会立即刷新地址、复制、发送示例和通知设置；不会重新
配对。自建通道不能成功注册时保持不可选并展示修复入口，不能影响官方通道。

## 收件箱

服务在 APNs 负载中提供 `drelChannelID`。通知扩展将其连同消息持久化；该字段仅供显示
与过滤，绝不用于鉴权、解密或敏感动作。收件箱默认按当前通道过滤；“全部历史”可查看
所有通道消息。切换后，另一通道的本地消息重新可见，不重新向服务器获取历史。

## Bark 兼容和隐私

自建服务保留 `/<deviceKey>/<title>/<body>` 和 JSON `POST /push` 的 Bark 风格接口，
也保留可选的 sender-side 加密信封。普通兼容接口的服务端可读取正文；加密信封使服务端
和 APNs 只能看到密文。官方服务不转发、读取或保存自建请求。

为发布版 Topic 直连 APNs 所需的凭据必须独立于现有 Cloudflare 托管签名凭据，并且仅限
`com.webbridgekit.superapp`。不得将现有私钥、设备 Token、二维码原始配对票据或可用
capability 写入仓库、日志或文档。是否创建并单独发布新的凭据是账号所有者后续的外部
安全决策，不属于本次代码变更。

## 删除与错误处理

删除自建通道时，客户端先请求精确注销，再立即销毁本地私钥与 capability；远程注销失败
不能阻止本地清除。旧 capability 重置后必须返回失败。不可用自建服务可重试或编辑；官方
通道始终保持可用。

## 验收

1. 官方和自建地址可同时存在，切换立即更新首页、复制和示例。
2. APNs Token 更新向所有启用通道完成注册。
3. 官方与自建各收一条消息；默认筛选和“全部历史”正确，切换不丢历史。
4. 重置后旧 capability 无法投递；删除后本地私钥不再存在。
5. 真机 TestFlight 验证前台、后台、锁屏、点击路由和无重复投递。
