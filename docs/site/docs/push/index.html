Push API

Use the copyable address from Drel as the base capability. Replace placeholders locally; never publish a real key in documentation, bug reports or source code.

Responses, retries and delivery

A successful direct request returns a JSON result shaped like {"code":200,"attempted":1,"accepted":1,"expired":0,"message":"…"}. Errors use {"error":{"message":"…"}}. Field counts can change as delivery targets change, so clients should read the status and handle errors rather than parse prose.

Accepted is not displayed. It means Drel accepted the request for APNs delivery. A device may be offline, disabled for notifications, or subject to iOS delivery policy. Senders should use an idempotency/revision strategy, exponential backoff for transient failures, and avoid automatic duplicate retries.

No numeric rate or payload-size service-level guarantee is published for the official endpoint. Treat 4xx, 429 and 5xx as failures; keep URLs concise and URL-encode path/query values.

Key rotation and privacy

Reset a push address from Drel Settings when it may have leaked. Update every sender to the newly copied address; a previously reset address must be treated as invalid. The official service processes the message to deliver it and is not an end-to-end encrypted channel. See Privacy and Terms.
