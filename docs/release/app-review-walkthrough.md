# Drel 1.0 审核演示脚本

这是给 App Review 审核人员的私有辅助材料，不是公开的 App Preview，也不是商店详情页的营销视频。
Drel 的核心流程跨越推送服务、iOS 通知和原生容器；审核人员不一定能自行复现「推送打开指定 HTTPS 页面」的完整流程。

## 录制前提

只能在 build 已处理完成、且真机 TestFlight 推送矩阵验证通过后录制。不能把模拟器或 Debug 包当作审核证明。视频中不得出现设备 Token、推送地址、网关密钥、个人通知内容或 API 凭据。

## 建议脚本（约 25 秒）

| 时长 | 画面操作 | 口播 / 字幕 |
| --- | --- | --- |
| 0–4 秒 | 打开 Drel 首页，停留在产品说明与推送入口。 | 「Drel 是面向开发者的消息通知工具，无需注册或登录即可使用。」 |
| 4–7 秒 | 显示通知已经开启的状态。不要录系统授权弹窗，也不要展示个人信息。 | 「通知权限仅用于接收开发者主动发送的消息。」 |
| 7–11 秒 | 从预先准备的、一次性的审核测试端发送一条普通推送。画面中隐藏请求地址和所有凭据。 | 「这里发送一条临时审核推送，推送中包含将要打开的网页路由。」 |
| 11–16 秒 | 展示通知到达，点击通知。 | 「收到通知后，点击即可打开该消息指定的 HTTPS 页面。」 |
| 16–23 秒 | 展示 Drel 容器打开预设 HTTPS 页面。 | 「Drel 1.0 只负责安全地打开 HTTPS 页面，不向网页注入原生 Bridge，也不允许网页调用原生能力。」 |
| 23–25 秒 | 停留在已打开的页面。 | 「推送只能导航，不能通过参数批准或执行敏感操作。」 |

## 在 App Store Connect 中的使用方式

仅当普通审核备注和临时审核流程不足以复现推送时，再作为 **App Review 附件**上传。它不能替代商店详情页所需的截图；审核备注仍要填写当前官方入口、支持链接、审核联系人，并明确说明无需登录。
